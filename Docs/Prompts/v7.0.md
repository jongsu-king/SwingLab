## 3. Work packages (in this order)

Each WP lists acceptance criteria (AC). A WP is **Done** only when its AC are met and verified. Otherwise it is **Partial**, with the gap stated.

### WP1 — Typed measurement provenance (fixes R7)

- In Core: `enum Provenance: String, Codable, Sendable { measured, visionDerived, audioDerived, estimated, simulated, userEntered, unavailable }`. `audioDerived` is a sub-kind of Measured for sensor-derived timing.
- Add `struct ProvenancedValue: Codable, Sendable { value: Double?; unit: String /* SI */; provenance: Provenance; confidence: Double? /* 0...1 */; method: String /* stable ID, e.g. "pose.wristPeak.v2" */; sampleCount: Int? }`.
- Replace the stringly-typed provenance, source (`"Recorded"`/`"Imported"`), and camera angle (`"Face-on"` …) with typed enums that have stable raw IDs and localization keys. Migrate existing stored values.
- App: a single `ProvenanceBadge` and `SLMetricReadout` (value, unit, badge, n) used for every metric on screen.
- **AC:** no string-literal provenance comparisons remain (grep proves it); schemaVersion-1 analysis JSON still decodes (test).

### WP2 — Pose pipeline v2 (fixes R2, R3, R4, R6, R8)

- **Two-pass sampling.** Pass 1: at most 30 Hz over the whole clip to locate the swing window. Pass 2: the native frame rate (up to 240 fps) from top − 0.35 s to impact + 0.35 s. Memory stays bounded: keep joints only, never frames.
- **Zero-phase smoothing** for offline data, in Core. Use a forward–backward filter or Savitzky–Golay, with the window derived from the actual sample interval. Remove causal smoothing from offline analysis. **AC:** on a synthetic trajectory, the smoothed peak time shifts by ≤ 1 sample interval at 30, 60, 120, and 240 fps (test).
- **Gaps:** interpolate only gaps of ≤ 2 dense samples, flag interpolated joints, and never draw across longer gaps.
- **Handedness:** a user setting (right/left) with a per-recording override. Lead/trail joints are derived from it.
- **Phase detector v2** (Core, `SwingPhaseDetector`, plain arrays in and out): all 8 phases, each with a time, a confidence, and the rule that fired. Document each rule in `Docs/PhaseDetection.md`. **AC:** synthetic swings at 30/60/120/240 fps with noise and dropouts recover address/top/impact within 1.5 sample intervals. Low-confidence phases come back as nil, not guessed (tests).
- **Merge fix (R8):** on re-analysis, user-entered markers override per phase. Estimates fill only the unset phases.
- **Optional 3D:** `VNDetectHumanBodyPose3DRequest` where supported (iOS 17+), labeled `visionDerived` 3D estimate. 2D stays the default.
- **Summary cache (R6):** stored attributes for tempo, backswing, downswing, head displacement, `analysisVersion`, and `poseFrameRate`, added via `SwingLabSchemaV2` and a migration stage with a migration test. Lists and charts must never decode pose JSON.

### WP3 — Audio impact detection (fixes R5; the highest-value honest measurement this round)

- Record mono AAC audio with the video in Swing and Ball modes. Add a localized `NSMicrophoneUsageDescription` in all 12 languages. If the mic is denied, recording still works video-only.
- In Core, `ImpactOnsetDetector`:
  - Compute a high-pass (≈ 2 kHz+) energy envelope or spectral flux and find transient candidates.
  - Choose the candidate inside the kinematic window (top → top + 0.6 s) nearest the pose-based impact estimate.
  - Confidence = peak-to-noise ratio. Reject when ≥ 2 comparable peaks fall in the window (driving-range neighbors).
- Audio and video share the movie file's timeline. Document the A/V sync assumption and its tolerance.
- Impact provenance is `audioDerived` only above a documented confidence threshold. Otherwise it is `estimated`. Works for imported clips that have audio.
- **AC:** tests on synthetic signals: a click in noise, two clicks, no click, a clipped click, and a click outside the window.

### WP4 — Practice sessions, consistency, coaching (fixes R13; v6.0 Phase 4)

- Add a `PracticeSession` model (date, club, camera angle, handedness, notes). Recordings belong to a session; recordings made within 90 minutes auto-group, and the user can regroup them.
- In Core: mean, SD, and CV for tempo, backswing, downswing, and head displacement, per club and camera angle. No consistency statement with n < 5; always show n.
- In Core, a coaching rule engine:
  - Rules compare against the user's **own** baseline (e.g., |z| > 1.5 vs. the last 20 swings with the same camera angle and club).
  - Output: a template ID + parameters → localized sentence in 12 languages.
  - No absolute good/bad judgments and no fault diagnosis without evidence.
  - Drills come from a short, curated list kept in `Docs/Coaching.md`.
- Swing comparison warns when camera angle, handedness, or frame rate differ.
- **AC:** rule-engine tests (n < 5 → no statement; baseline shift → correct template; mixed camera angles → excluded).

### WP5 — Ball flight physics engine (Core only)

- Integrate with RK4 (or adaptive RK45): gravity, quadratic drag, Magnus lift, wind (relative airspeed), and spin decay.
- Air density from temperature, pressure, and humidity (ideal gas + water-vapor partial pressure).
- Cd and Cl as functions of spin ratio (and Reynolds number if supported), from a **cited published model**. Write the citation and equations in `Docs/Physics.md`.
- Outputs: trajectory, carry, apex, flight time, landing angle, lateral deviation, and landing point. Carry and roll stay separate; roll is out of scope unless modeled honestly.
- Validation tests against widely cited TrackMan PGA Tour averages, with the source and tolerance stated in `Docs/Physics.md`. Example: driver ≈ 167 mph, 10.9°, 2686 rpm → ≈ 275 yd carry; 7-iron ≈ 120 mph, 16.3°, 7097 rpm → ≈ 172 yd. If you cannot confirm a reference value, mark it "unverified reference" and loosen nothing silently.
- App: a "Hypothetical flight" sheet in Ball Lab (inside the Swing tab). Inputs are user-entered, results are labeled `simulated`, and fields are never auto-filled from video.

### WP6 — Course geometry, hazard probability, caddie v2 (fixes R9, R10)

- **User-drawn polygons** per hole (fairway, green, bunker, water, penalty, OB): tap to add vertices, edit, delete. Stored as `userEntered` geometry.
- **OpenStreetMap import** (ODbL). Read `golf=fairway|green|bunker|tee|hole|water_hazard|lateral_water_hazard|rough` and `natural=water` via the Overpass API.
  - Show "© OpenStreetMap contributors" attribution, cache offline, and keep imported data user-editable.
  - Your sandbox may have no network. Implement the parser and mapping against checked-in fixture JSON with tests; make the live fetch a thin, failure-tolerant adapter.
- **Hazard probabilities:** use `GaussianDispersion.probability(in:)` over polygons projected into the aim frame. Show a probability only for geometry that exists; otherwise show "Unavailable".
- **Caddie v2** (Core):
  - Search clubs × lateral aim offsets (e.g., −30…+30 m in 2 m steps).
  - Objective = expected distance error + λ·variance + Σ wₖ·P(hazardₖ). Conservative/Balanced/Aggressive set λ and wₖ.
  - Account for carry vs. total (tee shots use total; approaches use carry).
  - Wind and elevation are used only if entered or measured, and are labeled.
  - Outputs: recommended club, aim point ("aim 8 m left of the flag"), expected landing zone, hazard risks, a safer alternative, and an aggressive alternative.
  - Template-based localized explanations.
- **AC:** tests for projection round trip, polygon probability against an analytic case (a rectangle aligned with an uncorrelated Gaussian), OSM fixture parsing, and the aim search moving away from a hazard.
- Weather: manual wind entry now. WeatherKit only behind a disabled feature flag (it needs a paid developer entitlement).

### WP8 — Localization integrity (fixes R12)

- Add a script, run by `Scripts/verify.sh`. It statically extracts every localization key from source, including the keys produced by typed enums. It fails if any key is missing in any of the 12 locales, or if any dynamic `text(variable)` call remains outside an approved enum-driven helper.
- Plural variants in `Localizable.xcstrings` for counts (swings, holes, shots, sessions). Use format strings with positional arguments for every sentence that includes values.

### WP9 — User-seeded club and ball tracking (no trained model required)

- **Club head:** the user taps the club head on the address frame; track with `VNTrackObjectRequest` through the backswing. Stop when confidence drops below a documented threshold, and show where tracking was lost. Label it `visionDerived`. Never extrapolate through impact.
- **Ball at address:** the user taps the ball, or the app proposes a small bright circular blob near the feet and the user confirms. Launch frame = the first post-top frame where the ball ROI changes beyond a threshold. Cross-check it against the audio impact.
- **Initial direction:** in the 1–4 frames after launch, detect the streak by frame differencing within a cone and fit a line. Report image-space direction only; no speed unless calibrated.
- **Ball-mode tracer** (down-the-line, sky background): background subtraction + blob detection + constant-acceleration Kalman filter with gating.
  - Observed points are drawn solid, short interpolated gaps dotted, and nothing is drawn after loss.
  - Export with the tracer via `AVMutableVideoComposition` + a Core Animation tool.
- Kalman, gating, and line-fit math live in Core, with synthetic-trajectory tests.
