# Course geometry and Caddie v2

Course areas are explicit user-entered polygons or community OpenStreetMap geometry. They are not surveyed boundaries. `CourseHole.referenceData` now stores a versioned JSON envelope containing point references and areas; the historical point-array format still decodes. Updating either collection preserves the other. No SwiftData attribute or schema version was added for geometry. Failed saves restore the exact pre-edit blob explicitly; this avoids depending on iOS 26 restoring live changed attributes after rollback.

The editor supports map taps, undo, replacing an outline, deleting an area, and an explicit Overpass import. Imported areas retain their OSM URL and estimated provenance; editing an imported outline changes its provenance to user-entered while retaining its attribution. Saved polygons are the offline cache. Failed imports leave saved geometry available. The request includes the area being viewed and runs only after the user selects Import. No background location is sent.

The parser reads closed `out geom` ways with `golf=fairway|green|bunker|tee|rough|water_hazard|lateral_water_hazard` and `natural=water`, plus `golf=hole` line geometry, reference number and par. It can also read a relation containing one complete closed outer ring and complete closed inner rings. It rejects open ways, fragmented relation rings, degenerate/crossing polygons and invalid coordinates. The live query requests ways; complex multipolygon assembly and automatic hole assignment are not implemented. The synthetic checked-in fixture is deliberately not represented as a real mapped course. Source documentation: [OSM golf tags](https://wiki.openstreetmap.org/wiki/Key:golf), [Overpass examples](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_API_by_Example), [ODbL attribution](https://www.openstreetmap.org/copyright).

`Geo.unproject` reverses the spherical projection into a shot's forward/right frame. Hazard probabilities integrate the existing bivariate Gaussian over supplied polygons; valid inner rings are excluded. Empty or invalid geometry never produces a zero-risk claim. The numerical integration is deterministic and approximate. Overlapping separate hazard areas are scored separately, so the summed penalties are not a union probability.

Caddie searches each eligible club and lateral offsets −30…+30 m in 2 m steps. For each aim it rotates the dispersion into that aim's frame, projects the supplied polygons, and minimizes squared mean distance error + λ·(forward variance + lateral variance) + Σ weight·P(hazard). Balanced weights are 900 m² for bunkers, 3600 m² for water/penalty areas and 6400 m² for OB. Conservative doubles these and uses λ=2; balanced λ=1; aggressive halves them and uses λ=0.5. These are disclosed engineering preferences, not calibrated strokes-gained weights. Conservative and aggressive searches are exposed as alternatives; they may select the same club and aim.

Approaches use entered carry; tee shots require entered total distance and never substitute carry silently. Existing forward/lateral dispersion is assumed to apply to either, clearly disclosed in the UI. Optional user-entered elevation distance and wind-drift adjustments shift the landing mean in the chosen distance unit. They are explicit landing assumptions, not measured wind or a validated wind-speed model. No coefficients translating wind speed or terrain into distance are invented. WeatherKit remains disabled. The selected aim and 80% conditional landing region appear on the map, and changing ball/target position clears a stale selection.

Validation added:

- `CourseGeometryTests`: projection round trip including the date line; uncorrelated rectangle probability vs the analytic Gaussian integral; excluded inner-ring probability; rejection of crossing/outside/duplicate holes; supported OSM tags and rejection of open geometry; aim moving away from water; no supplied geometry means no risk values; tee carry/total distinction.
- `CourseGeometryPersistenceTests`: legacy point arrays, polygon save/reopen, preserving polygons when editing points, and restoration after an injected save failure (both the visible object and a fresh persistence reader).

Core tests run on the macOS 27.0.1 (26A434) host (simulator device/runtime: none). The parent Round 4 report records actual iPhone 17 Pro / iOS 26.4 and iPhone Duo / iOS 27.1 runs for app integration. No real-course boundary accuracy, GPS accuracy or live Overpass-service availability is claimed by the synthetic fixtures.
